Thresholds
These four values reflect your environment's limits. A finding fires when one of them is breached. Set values that match your operational agreements — not system defaults.
ℹ
Rule sensitivity and detection logic are calibrated by Maintec for your environment and updated with each software release. These four thresholds are yours to set — they represent your organisation's SLAs and budget limits.
CPU warning threshold
A HIGH finding fires when peak CPU dispatch on any production LPAR exceeds this percentage of its entitled MSU. 80% is a common starting point — adjust to match your capacity planning SLA.
% of entitled MSU
Daily cost limit
A HIGH finding fires when estimated daily run cost exceeds this. Set it to your department's daily compute budget or the point at which someone needs to review a cost spike.
$ per run
DB2 buffer pool hit ratio
A MEDIUM finding fires when any DB2 buffer pool's hit ratio drops below this. IBM recommends ≥95% for production DB2 — lower means more physical disk reads. Only applies if DB2 data is present.
% minimum
Data staleness alert
An LPAR shows as Stale in System Health and a banner appears on the dashboard when its most recent SMF record is older than this. Set to about 1.5× your ingest cadence (daily ingest → 26–30h is typical).
hours
Changes take effect on the next ingestion run, not retroactively. Existing findings from the previous run are not recalculated.
DB2 data completeness
Two DB2 configuration items were detected as missing from your SMF data — they affect which findings fire
⚠
DB2 accounting CLASS 3 is not active
Lock wait times in the DB2 Accounting report show as zero. Lock contention findings won't fire. To enable: add ACCOUNTNG(CLASS(3)) to your DB2 DDF startup procedure — this requires a DDF restart only, not a full DB2 recycle.
⚠
DB2 statistics interval appears to be off (STATIME=0)
Only one buffer pool SMF 101 record per DB2 startup was detected — consistent with shutdown-only statistics. Buffer pool trend charts will be sparse. To fix: set STATIME 30 in DSNZPARM and recycle DB2.
